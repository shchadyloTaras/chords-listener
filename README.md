# Chords Listener

Вебсервіс, який визначає акорди пісні з посилання на YouTube (або будь-який сайт, який підтримує yt-dlp), з аудіо/відеофайлу чи просто слухаючи музику через мікрофон або вкладку браузера. Акорди підсвічуються в такт музиці, їх легко транспонувати, спрощувати й копіювати. Аплікатури є для гітари, бас-гітари, укулеле, фортепіано, фісгармонії й хендпана, а темп (BPM), удари такту й метроном допомагають грати разом із піснею.

Відкрий **https://shchadylotaras.github.io/chords-listener/**: усе відбувається на сайті, від реєстрації до результату, нічого встановлювати не треба (див. «Онлайн-версія»). Ту саму програму можна запустити й на своєму компʼютері (`./start.sh`): тоді сервер слухає лише `localhost`, а пісні зберігаються в папці `data/`.

## Вимоги

| Що | Навіщо | Як встановити (macOS) |
|---|---|---|
| **ffmpeg** | декодування аудіо й відео | `brew install ffmpeg` |
| **uv** | Python 3.11 і залежності бекенду | `brew install uv` |
| **Node.js 20.19+ / 22+** | збірка веб-інтерфейсу | `brew install node@22` |
| **git + Xcode Command Line Tools** | лише для першого встановлення (бібліотеку madmom зібрано з GitHub) | `xcode-select --install` |
| Інтернет | завантаження з YouTube і перше встановлення | |

Перевірено на macOS (Apple Silicon, M4 Pro). Браузер: Chrome, Safari, Firefox.

## Запуск

```bash
./start.sh
```

Скрипт перевірить інструменти й підкаже, чого бракує. Далі він сам:

1. робить `uv sync` у `backend/`;
2. запускає `npm install`, якщо його ще не було;
3. збирає інтерфейс, якщо `frontend/dist` відсутній або старіший за код;
4. запускає сервер на `127.0.0.1:8765` і відкриває **http://localhost:8765**.

**Ctrl+C** зупиняє сервер.

Перший запуск триває кілька хвилин, бо треба встановити залежності. Далі програма стартує за пару секунд.

Змінні середовища (необовʼязково):

```bash
CHORDS_PORT=8766 ./start.sh        # інший порт
CHORDS_NO_OPEN=1 ./start.sh        # не відкривати браузер
CHORDS_DATA_DIR=~/Music/chords ./start.sh   # де зберігати пісні
CHORDS_MAX_DURATION_MIN=60 CHORDS_MAX_UPLOAD_MB=1000 ./start.sh   # ліміти (типово 30 хв і 500 МБ)
```

> Відкривай саме **localhost**, а не 127.0.0.1: YouTube не показує відео на сторінках з IP-адресою. Якщо ввести 127.0.0.1, програма сама перейде на localhost.

## Онлайн-версія

**https://shchadylotaras.github.io/chords-listener/** — повноцінний сервіс. На головній сторінці є три способи почати:

- **Посилання.** Встав посилання на YouTube (або інший сайт): сервер у хмарі завантажить аудіо й розпізнає акорди.
- **Файл.** «Файл» або перетягни аудіо/відео будь-куди у вікно.
- **Слухати.** Мікрофон (пісня грає поруч: колонка, гітара, інший пристрій) або вкладка браузера. Акорди зʼявляються наживо, а після «Зупинити й зберегти» запис зберігається як пісня й розпізнається точно.

**Акаунт.** «Зареєструватися» (пошта й пароль) дає акорди з YouTube, точний аналіз на сервері й бібліотеку пісень на всіх пристроях. Без акаунта файли, мікрофон і відео з YouTube (через «Слухати у вкладці») теж працюють, але розпізнаються в браузері, а пісні зберігаються лише на цьому пристрої.

Поточний режим показано в шапці. Клік по ньому пояснює режим і відкриває налаштування.

| Режим | Коли | Що працює |
|---|---|---|
| **Хмара ✓** | ти увійшов в акаунт | усе: посилання, файли до 500 МБ, «Слухати»; точний аналіз на сервері, бібліотека в акаунті, видно на всіх пристроях |
| **Браузерний режим** | без акаунта | файли, «Слухати» й відео з YouTube через «Слухати у вкладці»; розпізнає браузер, пісні лишаються на цьому пристрої |
| **Локальний сервер ✓** | без акаунта, підключено власний сервер (розширено, див. нижче) | те саме, що в програмі на localhost |

### Слухати у вкладці (YouTube)

YouTube часто не пускає сервери дата-центрів (перевірка «Sign in to confirm you're not a bot»). Тоді, а також без акаунта, сайт сам відкриває «Слухати у вкладці»:

1. Відео вбудовано на сторінку. Натисни «Почати» (або «Почати з 1:23», якщо вже перемотав відео).
2. Chrome спитає, чи поділитися цією вкладкою. **Постав галочку «Також поділитися звуком вкладки»** і натисни «Поділитися». На сторінці є маленька картинка, як це виглядає.
3. Відео грає, акорди зʼявляються наживо. Пауза відео ставить на паузу й запис, перемотувати під час запису не можна.
4. Коли відео закінчиться або ти натиснеш «Зупинити й зберегти», запис іде на сервер (з акаунтом) або розпізнається в браузері (без нього). Пісня привʼязана до відео, тож акорди збігаються з вбудованим відео.

Працює в Chrome і Edge на компʼютері. Телефони й Safari/Firefox не вміють ділитися звуком вкладки: тоді сайт пропонує послухати мікрофоном (увімкни пісню на іншому пристрої поруч) або завантажити файл.

### Бібліотека

З акаунтом «Нещодавні» показують пісні з хмари. Пісні, розпізнані в браузері, позначені «На цьому пристрої»: кнопка «Перенести в хмару» (або «Перенести всі в хмару») надсилає їхнє аудіо на сервер, розпізнає там, переносить твої правки акордів і прибирає копію з пристрою.

### Власний сервер (розширено)

Необовʼязково: сайт без акаунта може працювати через Chords Listener на твоєму компʼютері.

1. Один раз завантаж програму і встанови інструменти з розділу «Вимоги»:
   ```bash
   git clone https://github.com/shchadyloTaras/chords-listener.git
   ```
2. Запусти сервер і не закривай термінал:
   ```bash
   cd chords-listener && ./start.sh        # CHORDS_NO_OPEN=1 ./start.sh — не відкривати вкладку localhost
   ```
3. На сайті клікни режим у шапці → «Розширено: власний сервер» → «Перевірити зʼєднання». Chrome (версія 142+) спитає, чи дозволити сайту доступ до пристроїв у локальній мережі. Дозволь: так браузер захищає localhost від сторонніх сайтів. Інший порт задай в «Адресі сервера» (наприклад, `http://localhost:8766`). «Не використовувати власний сервер» вимикає його.

Поки ти в акаунті, пісні розпізнає хмара, а власний сервер не використовується. Відкрий його напряму (http://localhost:8765), якщо потрібна саме локальна бібліотека.

**Безпека.** Сервер приймає запити лише від `https://shchadylotaras.github.io` і від сторінок на localhost: CORS, відповідь на Private Network Access-запит Chrome (`Access-Control-Allow-Private-Network: true`). Зміни з будь-яких інших сайтів, як і раніше, відхиляються. Список сайтів можна задати так: `CHORDS_ALLOWED_ORIGINS=https://один.example,https://другий.example ./start.sh`. Він замінює типовий, а сторінки з localhost дозволені завжди.

**Якщо сайт не підключається:** перевір http://localhost:8765/api/health; якщо в Chrome доступ до локальної мережі відхилено, дозволь його в налаштуваннях сайту (значок ліворуч від адреси) і перевір ще раз; Safari може не пускати сторінку https до http://localhost, тоді відкрий програму напряму.

### Публікація

`.github/workflows/pages.yml` на кожен push у `main` запускає тести, збирає інтерфейс з базовим шляхом `/chords-listener/` і публікує його на GitHub Pages (Settings → Pages → Source: GitHub Actions). Адресу хмарного API збірка бере зі змінної репозиторію `CLOUD_API_URL` (Settings → Secrets and variables → Actions → Variables); якщо її немає, діє адреса за замовчуванням у `frontend/src/config.ts`. Зібрати й переглянути так само локально (результат іде в `frontend/dist-pages`, а `frontend/dist` лишається для `./start.sh`):

```bash
cd frontend && VITE_BASE=/chords-listener/ npm run build
VITE_BASE=/chords-listener/ npx vite preview --port 5184   # http://localhost:5184/chords-listener/
```

**Перевірка без справжніх акаунтів** (емулятори Firebase, потрібна Java):

```bash
export PATH=/opt/homebrew/opt/openjdk/bin:$PATH
npx -y firebase-tools@latest emulators:start --only auth,storage --project build-chords-listener
cd backend && CHORDS_AUTH=firebase FIREBASE_AUTH_EMULATOR_HOST=127.0.0.1:9099 STORAGE_EMULATOR_HOST=http://127.0.0.1:9199 \
  CHORDS_UPLOAD_BUCKET=build-chords-listener.firebasestorage.app CHORDS_DATA_DIR=/tmp/chords-cloud \
  uv run uvicorn app.main:app --port 8783
cd frontend && VITE_BASE=/chords-listener/ VITE_FIREBASE_EMULATORS=true VITE_CLOUD_API_URL=http://127.0.0.1:8783 npx vite --port 5193
```

Відкрий http://localhost:5193/chords-listener/ і зареєструйся: акаунт створиться в емуляторі (Auth :9099), файли підуть в емулятор Storage (:9199).

## Хмарний сервер

Для тих, хто увійшов в акаунт на сайті, пісні розпізнає хмарний сервер: **https://chords-api-84488579848.europe-west1.run.app** (Google Cloud Run, проєкт Firebase `build-chords-listener`). Нічого встановлювати не треба. Кожен користувач бачить лише свої пісні, а файли зберігаються в Firebase Storage. Подробиці (API, авторизація, ліміти) описано в `docs/CLOUD.md`.

**Як оновити сервер** (потрібні `gcloud`, `node`, `openssl`, `curl`; Docker не потрібен, образ збирає Cloud Build):

```bash
./scripts/deploy_cloud.sh                 # усе: API, сховище, правила, збірка, розгортання (≈10 хв)
SKIP_SETUP=1 ./scripts/deploy_cloud.sh    # лише новий код
SKIP_BUILD=1 ./scripts/deploy_cloud.sh    # лише налаштування, без нової збірки
python3 scripts/smoke_cloud.py            # перевірити живий сервер (прибирає за собою)
```

Вхід у `gcloud` не обовʼязковий: якщо його немає, скрипт бере токен із входу firebase-tools (`npx firebase-tools login`, `scripts/gcloud_token.cjs`). Ключі сервера (`CHORDS_SIGNING_KEY`, `CHORDS_SMOKE_KEY`) створюються один раз у файлі `.cloud.env` у корені. Він не потрапляє в git, його не можна комітити. Якщо файл загубиться, скрипт створить нові ключі, і старі посилання на аудіо перестануть працювати. Логи сервера: `gcloud run services logs read chords-api --region europe-west1`.

**Ліміти.**

| Що | Ліміт |
|---|---|
| Розпізнавань на користувача за добу (UTC) | 40 |
| Розпізнавань вокалу на користувача за добу | 15 |
| Одночасних завдань у користувача | 2 (на всьому сервері одночасно аналізуються 2) |
| Файл через сайт | до 500 МБ (великі файли йдуть через Firebase Storage), запит напряму до API до 30 МБ |
| Тривалість пісні | 30 хв |
| Посилання на аудіо | діє 12 годин, потім сайт бере нове |

**Швидкість** (перевірено 5 жовтня 2026). Якщо сервер «спав», перша відповідь приходить приблизно за 9 секунд, а перша пісня готова приблизно за 12 секунд. Далі пісня на 4 хвилини розпізнається приблизно за 20 секунд, коротка пісня приблизно за 7 секунд, а пісня з YouTube на 3,5 хвилини (разом із завантаженням) за 20–35 секунд.

YouTube може не дати завантажити відео серверу з дата-центру (перевірка «Sign in to confirm you're not a bot»). Під час перевірки 5 жовтня 2026 завантаження з YouTube працювало, але таке блокування може зʼявитися будь-коли. Тоді завдання закінчується помилкою `download_blocked`, а сайт пропонує «Слухати у вкладці»: відео грає на сторінці, сайт записує звук вкладки й надсилає запис на сервер.

**Вартість** (тариф Blaze, europe-west1). Поки сервер працює, він коштує приблизно $0.37 за годину (4 vCPU + 16 ГБ). Без запитів він вимикається приблизно через 15 хвилин (мінімум 0 екземплярів), і тоді обчислення не коштують нічого. Безкоштовна квота Cloud Run покриває приблизно перші 8 годин роботи на місяць. Сховище коштує близько $0.02 за ГБ на місяць (пісня займає 5–10 МБ), образи в Artifact Registry ще до $0.3 на місяць (образ займає близько 0,9 ГБ, зберігаються 3 останні), збірки вкладаються в безкоштовні 2 500 хвилин Cloud Build на місяць. Захист від великих рахунків: не більше одного екземпляра (`max-instances 1`), денні ліміти на користувача, запит триває не довше години. Варто також увімкнути бюджет зі сповіщеннями в Google Cloud Billing. Зупинити сервер повністю: `gcloud run services delete chords-api --region europe-west1` (пісні в бакеті залишаться).

## Як користуватись

### 1. Додати пісню

- **Посилання.** Встав посилання на YouTube у велике поле: розпізнавання почнеться одразу. Підходять звичайні, `youtu.be`, `shorts` і `music.youtube.com` посилання; мітки часу й плейлисти в адресі ігноруються. Інші сайти теж працюють, якщо їх підтримує yt-dlp. Якщо YouTube не віддає відео серверу (або ти без акаунта на сайті), відкривається «Слухати у вкладці» (див. «Онлайн-версія»).
- **Файл.** Натисни «Файл» або перетягни файл будь-куди у вікно. Підходять mp3, m4a, wav, flac, ogg, opus, webm, mp4, mov і все, що відкриває ffmpeg.
- **Слухати.** «Слухати» → «Мікрофон» або «Вкладка браузера» → «Почати». Акорди видно наживо; «Зупинити й зберегти» зберігає запис як пісню й розпізнає його точно. Постав мікрофон ближче до джерела звуку.

Пісня тривалістю 3–4 хвилини обробляється приблизно за 3–6 секунд. Повторне посилання на вже розпізнану пісню, навіть в іншій формі, відкривається миттєво. Усі розпізнані пісні є в списку «Нещодавні» на головній сторінці.

### 2. Грати разом із піснею

- Вгорі сторінки великий **поточний акорд** (видно навіть з 2 метрів), **наступний** акорд, удари такту й аплікатура для гітари, баса, укулеле, фортепіано, фісгармонії чи хендпана (кнопки «<» «>» перемикають варіанти аплікатури).
- Поруч **темп**, наприклад «113 BPM», і точки ударів такту, які блимають у ритм. Клік по темпу відкриває панель темпу:
  - графік темпу протягом пісні;
  - **«Половина ×½ / Подвоїти ×2»**, якщо програма сплутала темп удвічі (такти, лічильник, метроном і копіювання підлаштуються);
  - **«Тап»** (клавіша T): настукай темп сам і порівняй з розпізнаним;
  - **метроном** (клавіша K) з гучністю: клацає на кожну долю, сильна доля звучить вище. Кнопка метронома є й у плеєрі.
- **Хендпан.** Діаграма показує інструмент згори: які поля грати для акорду, і чого бракує («бракує: B · грай як G5»). Над акордом видно, скільки акордів пісні грається на твоєму хендпані, і кнопку, яка транспонує пісню в найзручнішу тональність («Транспонувати +5 → 92 %»). Стрій вибирається там же або в налаштуваннях панелі (⚙): «Мій хендпан» (типово A | D F A C G E C A) чи готові строї (D Kurd, D Celtic Minor, C# Amara та інші). Олівець відкриває редактор власного хендпана: дінг і 7–14 полів, порядок, октави, вставка списком нот.
- Під ним **аркуш акордів** розбитий на такти. Поточний такт і акорд підсвічені, сторінка прокручується за музикою. Якщо прокрутиш сам, зʼявиться кнопка «Повернутись до відтворення».
- **Клік по акорду** перемотує пісню на нього, а на паузі ще й програє його звук. Наведення курсора (або довге натискання на телефоні) відкриває картку акорду з аплікатурою та кнопками «Прослухати», «Копіювати», «Редагувати» і «Грати звідси».
- **Звук акорду.** Акорд звучить на обраному інструменті й саме так, як показує аплікатура (з транспонуванням, спрощенням і знаками):
  - гітара й укулеле: показаний варіант аплікатури, перебором від верхньої струни; бас: усі ноти акорду в одній позиції, по черзі знизу вгору; фортепіано: ноти з нотного стану, бас лівою рукою трохи раніше; фісгармонія: ті самі ноти, тягучий язичковий звук; хендпан: лише ті ноти акорду, що є на твоєму хендпані, арпеджіо знизу вгору (якщо жодної немає, зʼявиться підказка);
  - звучить клік по акорду на аркуші й таймлайні (коли пісня на паузі; під час відтворення клік лише перемотує, і чути сам запис), по плитці в «Акорди в пісні», по великому поточному чи наступному акорду вгорі;
  - аплікатура звучить завжди: клік по гітарній, басовій чи укулельній діаграмі грає акорд, по клавіші фортепіано чи фісгармонії або полю хендпана — одну ноту, деінде на діаграмі — увесь акорд; ноти, що звучать, підсвічуються;
  - кнопка «Прослухати» в картці акорду й клавіша **P** (поточний акорд, а якщо його немає — виділений чи наступний) теж звучать завжди;
  - у налаштуваннях панелі (⚙) можна вимкнути «Звук акорду при натисканні» (тоді клік по плитці в легенді знову копіює назву) і змінити гучність, кнопка поруч із повзунком програє акорд для перевірки;
  - звук синтезується прямо в браузері (Web Audio), нічого не завантажується. На iPhone та iPad Web Audio слухається перемикача беззвучного режиму: якщо акорд не чути, а пісню чути, вимкни беззвучний режим.
- **Таймлайн** (перемикач у панелі або клавіша V) показує акорди як блоки на хвилі звуку, з масштабом (Ctrl/⌘ + колесо).
- Кольори акордів ідуть за квінтовим колом, тож споріднені акорди мають схожі кольори.
- Внизу плеєр: хвиля для перемотування, швидкість 0.5–1.5× без зміни висоти тону, гучність. Для пісень з YouTube є кнопка «Відео».

#### Живе фортепіано

Коли обрано фортепіано, під великим акордом зʼявляється **«Живе фортепіано»**: ноти пісні падають на клавіатуру, а клавіші натискаються й світяться саме тоді, коли нота звучить. Колір клавіші збігається з кольором акордів з такою ж основою, яскравість залежить від сили звуку, а на кожному натисканні клавіша коротко спалахує. Лінії з назвами акордів у стрічці показують, коли зміниться акорд.

- **Перше розпізнавання займає трохи часу.** Ноти знаходить нейромережа Basic Pitch (Spotify) прямо в браузері, на відеокарті: на Mac з M4 Pro це приблизно 0,7 с на хвилину звуку, тобто пісня на 15 хвилин готова за ~11 с. Без відеоприскорення розпізнавання значно довше (~30 с на хвилину). Поки воно триває, видно відсоток і кількість уже знайдених нот. Результат зберігається: на сервері в `data/tracks/<id>/notes.json`, у браузерному режимі в IndexedDB. Наступного разу ноти відкриваються миттєво, а після «Розпізнати заново» для акордів вони не зникають, бо звук той самий. Кнопка ↻ на панелі розпізнає ноти ще раз.
- **Синхронізація.** Якщо клавіші світяться раніше, ніж ти чуєш ноту (так буває з Bluetooth-навушниками, вони затримують звук на 100–300 мс), натисни «Синхронізація» й посунь повзунок праворуч. Якщо світяться пізніше, посунь ліворуч. Зсув запамʼятовується на цьому пристрої.
- Клавіатура підлаштовується під діапазон пісні (від 4 октав до всіх 88 клавіш). На телефоні видно ~3 октави, де звучить найбільше нот, а ноти поза ними переносяться на крайню октаву з позначкою ▲ / ▼.
- Звук акорду, який ти вмикаєш кліком, теж підсвічує клавіші, навіть на паузі. Якщо пісню транспоновано, клавіші показують ноти в новій тональності.
- Сховати панель можна кнопкою ✕, повернути вимикачем «Живе фортепіано» в налаштуваннях панелі (⚙). У демо-пісні звуку немає, тому немає й нот.
- **Точність.** На синтетичних записах з відомими нотами панель знаходить 98 % нот, 88 % знайденого правильні; початок ноти визначається з похибкою ~2 мс (у 90 % випадків до 8 мс). У щільних міксах з вокалом зайвих нот більше: модель чує й голос, і гармоніки інструментів.
- Якщо вокал розпізнано (див. «Ноти»), панель бере ноти з інструментальної доріжки без голосу, а мелодію голосу показує обведеними нотами й крапкою на клавіші, яку зараз співають. Кнопка з мікрофоном на панелі вмикає й вимикає це.

#### Ноти (вокал і фортепіано)

Кнопка **«Ноти»** поруч з «Акорди» й «Таймлайн» (або клавіша V) показує пісню нотами: окремо мелодію голосу й окремо те, що грають інструменти.

- **«Вокал»** — мелодія, яку співає виконавець, з її справжньою висотою й тривалістю. Її розпізнає сервер: натисни «Розпізнати вокал», і він відділить голос від музики й запише ноти (1–3 хвилини, етапи «Відділяю голос → Визначаю мелодію»). Над вокалом стоять назви акордів. У браузерному режимі вокалу немає, бо для нього потрібен сервер: увійди в акаунт або запусти `./start.sh`.
- **«Фортепіано»** — ноти інструментів на двох нотоносцях, для правої й лівої руки. Їх розпізнає Basic Pitch у браузері, як для живого фортепіано. Коли вокал уже розпізнано, ноти беруться з інструментальної доріжки без голосу; рядок під перемикачами показує, звідки вони.
- Перемикачі **«Вокал» / «Фортепіано» / «Акорди»** і **складність нот**: «Складний» записує всі розпізнані ноти (шістнадцяті, до чотирьох нот у кожній руці); «Середній» — восьмими замість шістнадцятих і з меншою кількістю нот в акордах, тож з аркуша читати легше; «Спрощений» — лише акорди пісні: акорд у правій руці й бас у лівій, як на діаграмі фортепіано. Для «Спрощеного» ноти інструментів розпізнавати не треба, тож партія фортепіано зʼявляється одразу.
- Курсор іде за музикою, сторінка прокручується сама (кнопка «стежити», F). Клік по ноті вмикає пісню з цього місця.
- **«Завантажити ноти»** (є й у меню біля «Копіювати»): **PDF** формату A4 (відкривається на iPhone, Android і компʼютері, друкується), **MusicXML** для MuseScore, Dorico, Finale й Sibelius, **MIDI** з доріжками «Вокал», «Фортепіано RH» і «Фортепіано LH» та темпом пісні для GarageBand, Logic тощо. Файл називається «Назва — ноти.pdf». Транспонування, спрощення акордів і знаки враховано.
- **Точність.** Це автоматична транскрипція. У щільних аранжуваннях партія фортепіано зводить кілька інструментів до двох рук, а дуже короткі ковзання голосу між нотами записуються як частина сусідньої ноти.

### 3. Транспонування й спрощення

- **− / +** у панелі (або `-` / `=`) транспонує на півтону, `0` повертає оригінал. Тональність показано як «Am → Cm».
- **«Спростити»** (S) показує прості акорди замість складних: Am7 → Am, G/B → G.
- **«Знаки»** перемикають написання: «Авто» (дієзи чи бемолі за тональністю), завжди `C#` або завжди `Db`.
- Якщо акорди легше грати з каподастром, зʼявиться підказка, наприклад «Капо 3: грай як Em C G D».

### 4. Копіювання

- **«Копіювати»** (або клавіша **C**) копіює всі акорди. Стрілка біля кнопки відкриває вибір формату:
  - **Такти:** `| Am | F | C | G |`
  - **З часом:** `0:12  Am`
  - **ChordPro:** `[Am]` для застосунків-пісенників
  - **Лише акорди:** `Am F C G`
- Там же можна завантажити `.txt` або `.cho`.
- Кожен рядок тактів має свою кнопку копіювання (зʼявляється при наведенні).
- Клік по номеру такту виділяє його, а Shift+клік виділяє діапазон. Потім можна «Копіювати» або «Зациклити» виділене.
- Кнопка копіювання на плитці в легенді «Акорди в пісні» копіює назву акорду (клік по самій плитці програє його звук).
- Скопійоване враховує транспонування, спрощення й обране написання знаків. Після кожного копіювання показується повідомлення й галочка.

### 5. Виправлення акордів

Подвійний клік по акорду (або F2 / E, коли акорд у фокусі) відкриває редактор з підказками. Зміни зберігаються одразу, і їх можна скасувати кнопкою «Відмінити» в повідомленні. Пункт «Скинути до розпізнаних» повертає оригінал. Пункт меню «Розпізнати заново» запускає аналіз ще раз; попередні правки при цьому зберігаються в резервній копії на диску.

### 6. Акаунт

«Зареєструватися» на головній сторінці (або «Увійти» в шапці) створює акаунт за поштою й паролем. На сайті він вмикає хмару: акорди з YouTube, точний аналіз на сервері й бібліотеку пісень на всіх пристроях (див. «Онлайн-версія»). Крім того, тема, мова, інструмент і вигляд акордів (спрощення, знаки, кількість тактів у рядку тощо) однакові на всіх твоїх пристроях. У програмі на localhost (`./start.sh`) акаунт синхронізує лише ці налаштування, а пісні лишаються на компʼютері. Без акаунта файли й мікрофон працюють у браузері.

### Гарячі клавіші

Клавіші не спрацьовують, поки курсор у текстовому полі. Вони працюють і з українською розкладкою. Повний список є у вікні `?`.

| Клавіша | Дія |
|---|---|
| Пробіл | відтворити / пауза |
| ← / → | назад / вперед на 5 с |
| Shift + ← / → | попередній / наступний акорд |
| `,` / `.` | повільніше / швидше |
| M | вимкнути / увімкнути звук |
| `-` `=` (або `[` `]`) | транспонувати вниз / вгору |
| 0 | оригінальна тональність |
| S | спрощені акорди |
| V | акорди → таймлайн → ноти |
| C | скопіювати всі акорди |
| F | стежити за відтворенням |
| L | зациклити поточний такт або виділення (ще раз — вимкнути) |
| I | гітара → бас → укулеле → фортепіано → фісгармонія → хендпан |

## Точність і поради

Розпізнавання працює на нейромережах [madmom](https://github.com/CPJKU/madmom), які переписано для швидкодії: пісня обробляється приблизно в 70–80 разів швидше, ніж звучить. Крім акордів, програма визначає ритм (долі й сильні долі), розмір 3/4 чи 4/4, темп і тональність. Якщо madmom недоступний, використовується запасний алгоритм на librosa.

**Результати тестів:**

| Набір | Збіг основи акорду | Збіг мажор/мінор | Тональність | Розмір |
|---|---|---|---|---|
| 8 синтетичних пісень | ~97 % | ~97 % | 8/8 | 8/8 |
| 14 випадкових синтетичних пісень | ~95 % | ~95 % | 14/14 | 14/14 |

На реальних записах відомі прогресії знаходяться правильно (наприклад, Em–C–G–D, G–D–Am–C).

**Що варто знати:**

- **Мажор і мінор іноді плутаються**, коли в аранжуванні звучить «чужа» терція або мінорний акорд зіграно арпеджіо.
- **Складні акорди показуються обережно.** Програма радше напише простий акорд, ніж вигадає зайвий: справжні 7, maj7 чи слеш-акорди іноді виходять звичайними тризвуками. Кнопка «Спростити» робить усе ще простішим.
- **Темп іноді визначається вдвічі повільнішим (або швидшим).** Буває в піснях без ударних. Акорди все одно на своїх місцях, але такти будуть удвічі довші. Виправ це одним кліком: клік по темпу → «Подвоїти ×2» чи «Половина ×½» (запамʼятовується для кожної пісні).
- **Акорди з низькою впевненістю** підкреслені пунктиром («Можлива неточність»).
- Розділення інструментів (Demucs) не встановлено, тому на дуже щільних міксах точність нижча.
- **Браузерний режим сайту** використовує легший алгоритм без нейромереж: на синтетичних піснях мажор/мінор збігається в ~91 % випадків (сервер ~95–97 %), а 7, maj7 і sus визначаються рідше. Для найкращого результату запусти `./start.sh`.

**Поради:**

- Оригінальний студійний запис дає кращий результат, ніж концертне відео чи кліп із вставками.
- Для запису з мікрофона потрібна тиша, мікрофон ближче до інструмента і хоча б кілька тактів гри.
- Якщо такти поставлені невдало, сітку ставить сама програма, а клік по акорду все одно перемотує точно на нього.
- Помилки легко виправити вручну (подвійний клік), а оригінал завжди можна повернути.

## Якщо щось не працює

**YouTube не завантажується** («Не вдалося завантажити», помилка 403). YouTube часто змінює сайт, тож онови yt-dlp:

```bash
cd backend && uv lock --upgrade-package yt-dlp && uv sync
```

Потім перезапусти `./start.sh`.

**«Відео недоступне для вбудовування».** Деякі власники забороняють показ свого відео на інших сайтах. Акорди й звук працюють як звичайно. Переконайся також, що відкрито `http://localhost:8765`, а не IP-адресу.

**Порт зайнятий.** `./start.sh` повідомить, якщо порт 8765 тримає інша програма. Подивитись, хто саме:

```bash
lsof -nP -iTCP:8765 -sTCP:LISTEN
```

Або запусти на іншому порту: `CHORDS_PORT=8766 ./start.sh`. Якщо програма вже запущена, скрипт просто відкриє її в браузері.

**Мікрофон не працює.** Запис можливий лише на `localhost` або через HTTPS. Дозволь доступ до мікрофона в налаштуваннях сайту в браузері.

**Перше встановлення падає на madmom.** Встанови інструменти розробника (`xcode-select --install`) і git, потім виконай `cd backend && uv sync`, щоб побачити подробиці.

**«Файл задовгий / завеликий».** Типові ліміти: 30 хвилин і 500 МБ. Змінити їх можна так: `CHORDS_MAX_DURATION_MIN=60 CHORDS_MAX_UPLOAD_MB=1000 ./start.sh`.

**Відкрити з телефону в тій самій мережі.** Сервер навмисно приймає лише localhost. Для доступу з мережі запусти бекенд з `--host 0.0.0.0` і `CHORDS_ALLOWED_HOSTS=<ip-компʼютера>`. Запис з мікрофона на телефоні без HTTPS не працюватиме.

**Почати з чистого аркуша.** Зупини сервер і видали папку `data/`. Окрему пісню можна видалити в меню сторінки пісні («Видалити пісню») або в списку «Нещодавні».

## Розробка

```bash
./dev.sh    # бекенд з автоперезапуском (127.0.0.1:8765) + Vite з HMR (http://localhost:5173)
            # інші порти: CHORDS_PORT=8766 CHORDS_DEV_PORT=5174 ./dev.sh
```

Перевірки:

```bash
cd backend && uv run pytest -q                       # API + рушій
cd backend && uv run python scripts/eval_engine.py   # точність рушія на синтетичних піснях
cd backend && uv run python scripts/analyze_file.py пісня.mp3   # акорди будь-якого файлу в терміналі
cd backend && uv sync --extra vocals                  # необовʼязково: розпізнавання вокалу (torch, Demucs, CREPE; ~600 МБ)
cd backend && uv run --extra vocals pytest -q         # тести разом із наскрізним тестом вокалу на справжніх моделях
cd backend && uv run --extra vocals python scripts/eval_vocals.py   # точність нот вокалу на синтетичних піснях
cd backend && uv run --extra vocals python scripts/eval_vocals.py --real пісня.mp3 --png ноти.png   # ноти вокалу файлу
cd frontend && npx tsc -b && npx vitest run && npx oxlint && npx vite build
cd frontend && node scripts/eval-web-engine.ts --dir <папка з синтетичними піснями>   # точність браузерного рушія
cd frontend && node scripts/eval-transcription.ts   # точність і швидкість розпізнавання нот (живе фортепіано)
```

Синтетичні пісні для оцінки: `cd backend && uv run python scripts/make_synthetic.py --out <папка>` (додай `--random 14` для випадкового набору).

Документація API доступна на http://localhost:8765/api/docs. Контракти (формати JSON, позначення акордів, API, клавіші, темп, режими сайту, Firebase і його емулятори) описано в `docs/SPEC.md`.
