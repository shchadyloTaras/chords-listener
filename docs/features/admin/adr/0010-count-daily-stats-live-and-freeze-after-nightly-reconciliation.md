# 0010 — Count daily stats live at event time and freeze each day after a nightly reconciliation

- **Status:** Accepted
- **Date:** 2026-10-07
- **Deciders:** Тарас Щадило (Tech Lead) + Claude під час Socratic-проходу `design`

## Context

Огляд показує підсумки поточної доби UTC, актуальні на момент відкриття (AC-01): аналізи за джерелами, транскрипції вокалу, невдалі задачі, активні (різні люди з хоча б однією прийнятою задачею) і нові користувачі. Firestore не рахує кількість різних значень одним запитом.

## Decision drivers

- NFR «Точність денної статистики» — розбіжність 0 з історією задач; підсумки завершеного дня після його кінця не змінюються (зокрема після видалення користувача).
- NFR «Вартість перегляду адмінки» ≤ 200 читань.
- KPI «Повнота денної статистики» ≥ 99% днів.

## Considered options

1. **Живі лічильники + нічна звірка** — атомарні інкременти документа дня в момент подій (перша задача людини за добу створює позначку «активний» і +1 активний); щоденна фонова робота перераховує вчорашній день з історії задач, виправляє й логує розбіжність, заморожує день.
2. **Підрахунок з історії на вимогу** — count-агрегації по історії задач для сьогодні, закриті дні пише нічна робота.

## Decision outcome

**Chosen:** Option 1. Огляд коштує 1–2 читання; активні користувачі рахуються без читання всіх задач дня; точність гарантує звірка, а заморожений день не змінюється.

## Consequences

**Positive**
- Дешевий огляд; KPI «повнота» вимірюється розбіжностями звірки.
- Знеособлення при видаленні не чіпає заморожені дні.

**Negative**
- Два шляхи підрахунку (живий і звірка) — логіку категорій треба тримати спільною.
- Звірка читає всі задачі дня (фонова робота, не екран — бюджет 200 читань на неї не поширюється).

**Neutral**
- Нові користувачі за добу рахуються count-агрегацією по `users` за часом створення; дні до запуску фічі відновлюються разово з пісень (AC-08) і позначаються «відновлено з пісень».
