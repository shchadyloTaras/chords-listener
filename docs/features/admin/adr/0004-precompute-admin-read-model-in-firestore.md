# 0004 — Precompute the admin read model as Firestore projections written at event time

- **Status:** Accepted
- **Date:** 2026-10-07
- **Deciders:** Тарас Щадило (Tech Lead) + Claude під час Socratic-проходу `design`

## Context

Зараз немає ні довідника користувачів з лічильниками, ні збереженої історії задач (лише в пам'яті), ні статистики; дані розкидані по файлах кожного користувача в GCS. Адмінка має показувати списки, картки, історію й статистику, не скануючи сховище.

## Decision drivers

- NFR «Вартість перегляду адмінки» — ≤ 200 читань сховища на один екран чи одну сторінку списку, незалежно від загальної кількості користувачів і пісень.
- NFR «Зберігання історії задач» ≥ 90 днів; «Зберігання журналу» ≥ 365 днів, записи незмінні.
- NFR «Точність денної статистики» — розбіжність 0, підсумки завершеного дня не змінюються.
- NFR «Повнота видалення» — знеособлення записів журналу й історії задач.
- §2 — Firestore уже в стеку (REST-клієнт сервісного акаунта).

## Considered options

1. **Проєкції у Firestore** — сервер у момент подій пише довідник користувачів, запис задачі, атомарні інкременти денної статистики, журнал — у закриті для клієнтів колекції.
2. **Логи → BigQuery** — структуровані логи в Cloud Logging із sink у BigQuery; статистика й історія — SQL; довідник і стани все одно у Firestore.

## Decision outcome

**Chosen:** Option 1. Кожен екран — кілька десятків читань готових документів; TTL-політики Firestore (автовидалення документа за полем-датою) дають 90/365 днів; знеособлення — оновлення документів.

## Consequences

**Positive**
- Виконується бюджет ≤ 200 читань і точність статистики (інкремент у момент події).
- Немає нового сервісу в стеку.

**Negative**
- Денормалізація: проєкції треба тримати узгодженими з GCS-даними; для існуючих користувачів і пісень потрібне разове заповнення (backfill), зокрема відновлення днів «відновлено з пісень» (AC-08).
- Кожна задача й аналіз додають кілька записів Firestore.

**Neutral**
- Колекції й поля деталізує етап `data-model`; аналітичне сховище можна додати пізніше як ще одну проєкцію.
