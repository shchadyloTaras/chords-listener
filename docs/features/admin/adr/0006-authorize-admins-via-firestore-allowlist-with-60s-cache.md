# 0006 — Authorize admins via a Firestore allowlist checked on every request with a 60-second cache

- **Status:** Accepted
- **Date:** 2026-10-07
- **Deciders:** Тарас Щадило (Tech Lead) + Claude під час Socratic-проходу `design`

## Context

Ролей і кастомних claims сьогодні немає; сервер сам перевіряє ID-токен Firebase. Права видає лише скрипт власника (spec §3); зняття прав має діяти ≤ 60 с (AC-32), хоча ID-токен живе годину; остаточні дії вимагають входу не давніше 15 хв (AC-34).

## Decision drivers

- AC-31, AC-36 — не-адміністратор бачить лише «Сторінку не знайдено», без підказок, що адмінка існує.
- AC-32 / NFR — зняття позначки адміністратора діє ≤ 60 с.
- AC-34 — повторний вхід для запланованого видалення й паузи нових аналізів.
- Spec §3 — права видає лише скрипт власника; викрадена сесія не може додати адміністраторів.

## Considered options

1. **Allowlist у Firestore + кеш 60 с** — закрита колекція адміністраторів, яку пише лише скрипт власника; сервер перевіряє uid на кожен `/api/admin/*` з кешем ≤ 60 с; повторний вхід — за `auth_time` ID-токена.
2. **Custom claim + перевірка відкликання** — `admin: true` у токені, зняття = відкликання сесій; сервер на кожен адмінський запит питає Identity Toolkit, чи не відкликано.

## Decision outcome

**Chosen:** Option 1. Найпростіша модель, що виконує ≤ 60 с без звернення до Identity Toolkit на кожен запит; клієнт не отримує жодного сигналу про роль, поки сервер не відповість.

## Consequences

**Positive**
- ≤ 1 читання Firestore на хвилину на перевірку прав.
- Зняття прав не розлогінює людину на основному сайті.
- Немає підказки про роль у токені — узгоджується з AC-31.

**Negative**
- Адмінка дізнається, що людина адміністратор, лише з першої відповіді сервера (зайвий запит при відкритті).
- Скрипт власника потребує доступу сервісного акаунта до Firestore.

**Neutral**
- `auth_time` перевіряє сервер для запланованого видалення й увімкнення паузи нових аналізів; адмінка робить перевхід і бере свіжий токен.
